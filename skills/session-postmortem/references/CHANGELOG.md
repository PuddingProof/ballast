# Report schema-version history

The `**Schema version:**` line in each report's header marks the report *format* it was produced with, so a reader (or a future §5 trend-miner) can spot a stale-format report at a glance. Bump it when the report's **section structure** changes — a top-level `##` section added / removed / renamed, a header metadata field added / removed / renamed, or a field's machine-readable format changed. Do **not** bump for prose rewording or adding a subsection within an existing `##`. The live value is emitted by `SKILL.md`'s report template; record every bump here.

Two header/structure changes, batched:

**Header:**
- New OPTIONAL header field **`Plan promotion:`** — orchestrator-authored judgment call (SKILL.md step 6's plan-promotion check) recording whether an approved plan that lived only outside the repo (a native plan-mode save, or in-context only) was promoted to the project's durable spec home; emitted only when the session executed an approved plan (`promoted → <path>` or `not needed — <one-clause reason>`). **§6 escalation semantics:**
- **🔴 ESCALATED redefined** — carried open ≥2 reports now requires FRESH evidence (a new occurrence or live exercise in the carrying session) to escalate; a bare keepalive carry no longer counts. Restores parity with §5, which counts occurrences, not carries. A carry with no fresh evidence is annotated **`— dormant`** (new glyph-legend annotation, not a new counter) and never escalates on its own; a chain gone cold still uses the existing drop disposition. **Carve-out:** a waiting-on-owner cross-repo handoff is dormant by design — never escalates, never drops on dormancy alone; its disposition comes only from the `~/.claude/postmortem/HARNESS-RECS.md` ledger.

**Procedural (no schema bump) — 2026-07-22:**
- **Auto-apply boundary now requires an explicit `--fix <grant>`** (`memory`/`ideas`; bare `--fix` = both) — the default flipped from auto-applying the bounded memory/idea-tracker classes to **propose-everything**; nothing is applied without the grant. The step-6 commit step gained two preconditions before it commits: a **secret/PII scrub** of the report content itself (don't rely on the commit-time guard reminder alone), and **standing-rules-win** — the auto-commit defers to a standing CLAUDE.md prohibition or a permission-config gate on `git commit` rather than routing around it. Provenance: governance-alignment PR #1 item 4.
